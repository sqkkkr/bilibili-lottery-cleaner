# B站抽奖动态清理器

版本 1.0.2，MIT 协议。有油猴脚本和浏览器扩展两种装法，共用同一套源代码与判定逻辑，安装时选择一种即可。

用来删自己空间里已经开完奖的转发抽奖动态。

做它的原因很简单：转发抽奖转多了，动态页会被历史抽奖刷屏，一条条手删很累；但直接批量删又不敢，没开奖的删掉，抽奖资格就作废了。所以这个工具只碰"已经开完奖、留着也没用"的那些，其余一概不动。

## 安装

### 方式一：油猴脚本（推荐）

先装 [Tampermonkey](https://www.tampermonkey.net/)。装完还有一步别漏：Chrome / Edge 的扩展管理页要打开「开发者模式」，再进 Tampermonkey 的详情页把**「允许运行用户脚本」**打开，不然脚本不会执行。

然后选一个源，点开就会弹出油猴的安装页：

- [GitHub（推荐）](https://github.com/sqkkkr/bilibili-lottery-cleaner/raw/main/bilibili-lottery-cleaner.user.js)
- [GreasyFork](https://greasyfork.org/zh-CN/scripts/600946)（国内能访问，装完自动更新）
- [jsDelivr（备用）](https://cdn.jsdelivr.net/gh/sqkkkr/bilibili-lottery-cleaner@main/bilibili-lottery-cleaner.user.js)

装完打开自己的空间动态页，刷新一下，右下角出现按钮就生效了。

以后脚本有更新，油猴会自己检查并提示，不用手动重装。

### 方式二：浏览器扩展（备用）

方法一失效的话用这个。要求 Chrome 或 Edge 111 以上——插件用到了 MV3 的 `world: "MAIN"`，这个字段从 111 才开始支持，所以清单里写了 `minimum_chrome_version`，版本不够浏览器会直接拒绝安装。

1. 去 [Releases](https://github.com/sqkkkr/bilibili-lottery-cleaner/releases) 下载 zip
2. 解压到一个固定位置，别放临时目录，那个目录删了插件就失效
3. 地址栏打开 `chrome://extensions`（Edge 是 `edge://extensions`）
4. 打开右上角的开发者模式（Edge 在左下角）
5. 点「加载已解压的扩展程序」，选中**里面含 `manifest.json` 的那一层文件夹**
6. 打开 `https://space.bilibili.com/你的UID/dynamic` 刷新一下，右下角出现按钮就装好了

两种装法都只在个人空间的动态页启动。首页、视频页、别人的空间都不会出现面板，也不会发请求。

## 怎么用

打开自己的动态页，点右下角按钮，点「扫描」。等它把列表读完，面板顶部会出来三个数字：已开奖、未开奖、已跳过。

在列表里核对一遍。点「全选官方已开奖」只勾选官方接口确认的已开奖条目。标有「文本」的条目需要打开原文核对后逐条勾选。勾完点「删除选中」，确认框会写清楚删多少条、大概要多久。确认后开始逐条删，想停随时点「停止」。

列表默认只显示已开奖和未开奖，想看全部就勾上「显示已跳过」。每行右边独立显示「转发动态」「原动态」链接，未开奖条目也能打开核对，链接不会被长说明截掉。取不到原动态 ID 时只显示可用链接。

## 怎么判定

动态列表是直接翻接口拿的，一页页翻到底。接口不通的时候才退回页面下滑解析，但页面链接不能证明属于本人转发，所以这条路仅供核对，一律进不了删除队列。

每一条动态进来，先看是不是转发。不是就直接跳过，原创动态不做任何判断。

确认是转发，就拿**被转发的原动态 ID**去查官方抽奖：

- `status = 2`（已开奖）→ 可以删
- `status = 0`（未开奖）→ 保护
- 查不到 → 看文案里有没有「抽奖」「开奖」

文案里有时，解析开奖日期。**未写年份时按自己转发该动态的年份解析**；缺少转发时间则不猜年份。支持月日、月/日及明确时分，没写时刻按当天结束计算；非法日期不会放行。日期已经过了就列为可删，但会标上「文本」，提醒你人工核对；日期还没到就保护；解析不出日期就跳过。按最初定的规则，没写开奖时间的一律不动。

文案里没有，跳过。

查询最终未取得可靠结果（包括部分版本失败且其他版本为空、超时、无效响应结构）时按保护处理；其他版本已经返回明确官方结果时可采用该结果。“未开奖”分组也包含这些暂时无法确认的条目，应查看具体原因。

有个地方特别容易搞错：查抽奖状态要用被转发的原动态 ID（`item.orig.id_str`），用自己那条转发动态的 ID 永远查不到东西。而删除时发的才是自己的动态 ID，这两个不是一回事。

## 不会动的东西

- 自己发的原创动态，不判断，直接跳过
- 还没开奖的抽奖，勾选框是禁用的
- 提到抽奖但没写开奖时间的
- 接口最终无法确认、日期格式不支持或判定不出来的
- 没有「全自动删除」这回事，每一步都要你自己点

## 用到的接口

| 用途 | 接口 |
| --- | --- |
| 动态列表 | `GET https://api.bilibili.com/x/polymer/web-dynamic/v1/feed/space?host_mid={UID}&offset={offset}` |
| 抽奖状态（v2） | `GET https://api.vc.bilibili.com/lottery_svr/v2/lottery_svr/lottery_notice?dynamic_id={原动态ID}` |
| 抽奖状态（v1） | `GET https://api.vc.bilibili.com/lottery_svr/v1/lottery_svr/lottery_notice?business_id={原动态ID}&business_type=1` |
| 删除动态 | `POST https://api.bilibili.com/x/dynamic/feed/operate/remove?platform=web&csrf={bili_jct}` |
| WBI 密钥 | `GET https://api.bilibili.com/x/web-interface/nav` |

抽奖状态优先查询上次可用的版本；返回空数据或失败时仍检查另一版本。无法取得有效查询结果时保护该条目，不用文本日期放行。

`status` 里 0 是未开奖，2 是已开奖；`lottery_time` 是秒级时间戳。删除请求体是 `{ dyn_id_str, rid_str }`，`csrf` 取 Cookie 里的 `bili_jct`。

有些接口要 WBI 签名（`w_rid` 加 `wts`），插件会自己补签名重试，不用管。

所有请求都在页面上下文里发（`world: "MAIN"`），自动带登录 Cookie，不做额外处理，也不往第三方传数据。

## 配置

扩展版改 `src/config.js` 后，在扩展管理页重新加载，再刷新动态页。油猴版改源代码后需重新构建并导入生成脚本。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `dryRun` | `false` | 改成 `true` 就是演练模式，只列清单不真删 |
| `requireConfirm` | `true` | 删除前弹确认框，建议开着 |
| `apiPageMax` | `200` | 接口最多翻多少页 |
| `probeGap` | `350` | 每条抽奖查询之间等多少毫秒，别调太小 |
| `delMin` / `delMax` | `3000` / `8000` | 删除间隔，毫秒 |
| `delWarnOver` | `20` | 一次删超过多少条时多提醒一句 |
| `riskPause` | `60000` | 碰到风控码暂停多久 |
| `lotteryKeyword` | `/抽奖\|开奖/` | 文本兜底用的关键词 |

表里只列了常用的几个。下滑兜底的等待时间、单次请求超时、调试开关这些也在这个文件里，注释都写清楚了。

```
bilibili-lottery-cleaner/
├── bilibili-lottery-cleaner.user.js  油猴版，由 tools 构建生成，不要手改
├── manifest.json        扩展清单（MV3）
├── icons/               16 / 32 / 48 / 128 四档图标
├── src/
│   ├── config.js        全局配置，调参只改这里
│   ├── md5.js           极简 MD5，给 WBI 签名用
│   ├── utils.js         工具函数和全局状态
│   ├── net.js           请求封装、WBI 签名、动态列表、删除接口
│   ├── parser.js        动态字段解析
│   ├── lottery.js       核心判定，查抽奖状态、解析文本日期
│   ├── scanner.js       扫描流程，翻接口然后逐条判定
│   ├── deleter.js       删除流程，过滤、限速、串行删
│   ├── ui.js            面板界面
│   └── main.js          入口装配
├── styles/panel.css     面板样式
├── test/                本地测试，不需要浏览器
├── tools/               构建脚本（打包油猴版、生成图标）
├── CHANGELOG.md         版本变更记录
├── TESTING.md           测试覆盖范围与人工验证步骤
├── LICENSE
└── README.md
```

油猴版是从 `src/` 打包出来的单文件。改完代码要跑一遍：

```bash
python tools/build_userscript.py
```

它会按顺序拼模块、把 CSS 内联进去，版本号自动从 `src/config.js` 读。


模拟接口不会操作真实账号；覆盖范围和人工验证步骤见 [TESTING.md](TESTING.md)。构建只写当前仓库，并检查清单版本及模块顺序。

## 常见问题

**扫出来 0 条**

先确认停在 `space.bilibili.com/你的UID/dynamic`，而且已经登录。面板日志区会写接口返回的 code，点「复制日志」贴出来就能定位。

**条数比实际少**

先看三个分类的总数：列表默认隐藏“已跳过”，显示的行数不等于读取总数。分页会沿新游标继续，重复页或空页不会直接视为到底；暂时失败最多重试两次。若游标循环、接口异常或达到 `apiPageMax` 上限，会显示“扫描未完整”及原因，保留已读结果。只有提示达到页数上限时才需要调大配置。

**点删除没反应**

先确认在登录账号本人的动态页，并已勾选合格条目。未开奖、已删除和页面兜底条目不能勾选；文本判定需逐条核对。扫描与删除不能同时进行。停止后可再次删除剩余选中条目，切换账号或空间后需重新扫描。

**首页提示页面展示可能受插件影响**

这是展示兼容性提示，单凭提示不能确定触发插件。本插件匹配 `space.bilibili.com`，面板只在本人动态页出现；已移除页面网络函数拦截，CSS 通用类限定在面板根节点内。排查时只保留一种安装形式，分别启停本插件并刷新首页对照，再检查其他扩展。不能承诺更新后提示一定消失。

**识别时间仍不正确**

没写年份按转发年份，不推测跨年；没写时刻按当日结束。模糊相对时间、图片里的规则和不支持的格式会跳过，不能把“已开奖·文本”当成官方确认。浏览器本地时区参与日期解析，非中国时区使用前应额外核对。

**会不会被封号**

插件只调官方 Web 接口，不模拟点击也不刷量，请求之间都隔了几百毫秒。但自动化工具总有风险，自己控制频率，量大的话分批来。

**改了代码没变化**

到扩展管理页点一下这个扩展的刷新按钮，再刷新动态页。右下角按钮上写着版本号，可以判断有没有生效。

## 几句提醒

删了就是真没了，插件不备份。第一次用建议先勾三五条试删，确认判定准了再批量来。

几十条一起删要几分钟，期间别关页面，可以点停止。

停止会阻止下一条请求；已经发出的删除请求可能已在服务器生效。遇到超时或页面中断，先重新扫描核对实际结果，不要把超时当作删除已回滚。

B 站接口随时会改，哪天突然扫不出来，多半是接口变了。

这是给自己清理动态用的工具，用的时候守一下 B 站的用户协议。
